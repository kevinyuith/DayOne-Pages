# Project rules

## Language: everything in English

- **The whole repo is in English**: code, identifiers, comments (TS, PHP, SQL), docs, commit messages, test names, log messages, routes and query params (`/templates`, `/domains`, `/funnels`, `/settings`, `?folder=`, `?days=`). The old Portuguese addresses (`/paginas`, `/dominios`, `/funil`, `/configuracoes`) only redirect, in `next.config.ts`.
- **Database** (Supabase, schema `pages`): tables, columns, functions, parameters, indexes, constraints, CHECK/enum values, `COMMENT ON`, `RAISE` messages and comments. When a database error reaches the screen, the action translates it by error code (e.g. `23514`) instead of showing the raw message.
- **UI**: dashboard (menu, titles, buttons, confirmations, action/lib error messages, labels), `<html lang="en">`, dates and numbers in `en-US`, and the pages the PHP server returns to visitors (403/410/451/503). The dashboard has `translate="no"` on `<html>` so the browser does not translate it.
- The only other languages are per-visitor-language data: the month/language-name tables of `{{date}}`/`{{language}}` (`placeholders.ts` = `placeholders.php`) and the legal suffixes of `company.name` (LLC, Ltda, GmbH…).
- **No explanatory text on screens**: the header is only the title (`PageHeader` has no description) and there are no footnotes explaining the screen or the metrics. Labels, empty states and error messages stay.
- **Time in UTC**: every date is `timestamptz` (never `timestamp` without time zone) and the database runs in UTC. Functions take and return instants and never convert time zones: no `AT TIME ZONE` nor fixed zones in SQL. Grouping by local day is the frontend's job.

## Pages: one table for every page

- **Every page lives in `pages.pages`**, its slugs and HTML included, in the `slugs` column: `{ "/path": { title, content, content_type, is_active, content_hash, created_at, updated_at } }` (`content_hash` = sha256 of the HTML, filled by a trigger). `scope` says what it is: `TEMPLATE` (the Page templates screen, `/templates`; never served, never FUNNEL), `DOMAIN` (served by one domain) or `FUNNEL` (a page of a funnel). There is no `page_slugs` table. **Never `select("*")` on `pages`** (it carries the HTML): read through `pages.pages_summary` / `domain_pages_summary` / `funnel_pages_summary`, and one slug's HTML through `page_slug_get` / `domain_slug_get` / `funnel_slug_get`.
- **`pages.domains.site` and `pages.funnels.site` are only lists**: `{ "<page id>": {} }` and `{ "<page id>": { "weight": 50 } }`. A page is listed by exactly one domain or funnel (triggers); removing it from the list deletes the row, and deleting the domain or funnel deletes its pages. `default_page_id`, `filter_pass_page_id` and `filter_fail_page_id` must be pages in the domain's list (triggers). A domain serves, in order: bot block (`block_bots`, 403) → filter (pass/fail page) → default page, with the request path as the slug. There are no per-path routes (`domain_routes` was dropped in 20260924q).
- **Writes only through the functions**: `page_save` and `page_slug_create/rename/set_active/delete` for any page (they lock the row and use optimistic concurrency on `updated_at`; the last slug of a page is not deleted), the `domain_*` wrappers (check the page belongs to the domain) and the `funnel_*` wrappers (same for the funnel). Templates are created with a plain insert (`scope: "TEMPLATE"`, `slugs`).
- **Domain pages are copies**: of a template (`domain_page_copy`, `domain_page_add` for a variation) or of the pages of a funnel (`domain_funnel_copy`), recorded in `template_id` / `funnel_page_id` + `funnel_id`. From then on they are independent: editing the copy does not change the source and vice versa (the funnel A/B share is the exception: it is read live). "Change template" replaces the copy (`domain_page_replace`, same id, edits lost).
- **Folders of the Templates screen are paths, not rows**: a template keeps its folder in `pages.pages.folder` (`"Funnels/F23/White"`, NULL = the root; segments of 1–80 characters without `/` nor spaces at the ends, up to 10 levels, templates only — `pages_folder_path`). The tree comes from the paths (`src/lib/pages/folders.ts`, `foldersFromPaths`); a folder exists while a template is in it — a new, still empty folder lives on the screen for the browser session. Renaming/moving/deleting a folder rewrites its templates' paths in one statement (`pages.template_folder_move` / `template_folder_delete`: deleting moves what was inside up one level). Changing only the folder doesn't touch `updated_at` (the trigger skips it), so moving a template never makes an open editor see a conflict. There is no `pages.folders` table.
- **One editor** (`src/components/editor/page-editor.tsx`), with actions and links coming from the route: template at `/templates/[id]/edit?slug=/path`, funnel page at `/funnels/[pageId]/edit?slug=/path`, domain page at `/domains/[id]/pages/[pageId]?slug=/path`. A slug's id is its path. A funnel page is a single slug (`/`), so its editor has no Pages (slugs) tab in the rail — it opens on the Funnel panel (`src/components/editor/rail.tsx`).
- **The Source panel** (rail "Source", `src/components/editor/panels/source-panel.tsx`) shows the slug's one HTML document as three editors — HTML, Page CSS, Base CSS — split and joined by `src/lib/pages/source-split.ts` (`joinSource(splitSource(html))` gives the same HTML back). **Page CSS** is the page's own `<style data-dop-css>`, kept as the last thing in `<head>` (so it wins) and dropped when empty; **Base CSS** is every other `<style>` in page order, left in the HTML as a `/* Base CSS #N */` marker. Nothing new is stored: it is all in the slug's HTML. Live updates apply a draft after a pause in typing (a CSS-only change is patched into the canvas without a reload); "Edit with AI" (`src/lib/pages/code-ai.ts`) uses the same Kimi/Claude keys as the copy angle and only fills the editor — nothing is saved until Save.
- **VTurb players in the editor** (`src/lib/pages/vturb.ts`): the canvas runs without scripts, so a `<vturb-smartplayer>` (0px tall there) is drawn the way VTurb shows it before the video loads — a 16:9 box with the video's `cover.jpg` (images.converteai.net, the account taken from the page's player script), a play button and a label with its id. It's CSS in the canvas' editor style (`injectCanvasChrome`'s extra CSS: `serialize` drops it and `patchStyles` skips it), so the page's HTML never changes. A `{{video_id}}` player shows the funnel's VSL with the largest share (`getFunnelPageForEditor` → `vturbStandIn`; ties by name); an A/B player (`ab-…`) or an unknown id gets the box without a cover. The Preview runs the page's scripts, so a real video plays there; only an unresolved `{{video_id}}` player gets the same drawing (`withVturbPreview`).

## Delivery server and cache

- **The connections to Supabase and dot stay open between requests** (`http_share()`/`http_curl()` in `server/src/supabase.php`): one `curl_share_init_persistent` (PHP ≥ 8.5, the site's php-fpm) per worker keeps the connections, TLS sessions and DNS answers. A new HTTPS connection costs ~14 ms of CPU, a reused one ~0.5 ms — in a crawler burst, the new connections were ~90% of a request's CPU. Older PHP (the CLI `php` on the server is 8.4) opens one per call, as before.
- `pages.resolve(host, path, key, p_with_content => false)` returns only the decision (routes, conditions, A/B split) and each slug's `content_hash`; the HTML comes through `pages.content_get([{ page_id, slug }])` only for hashes that are not on disk (`cache/content/<hash>.php`, never invalidated — a hash never changes content; the cleanup removes files no route used for `STALE_MAX_AGE` + 1 day). The server re-checks the decision every `CACHE_TTL` (30 s) with SWR on (the visitor gets the stored copy; the check happens after the response). `p_with_content` defaults to `true` only for servers that are still on the old code.

## The traffic gate (rules), on every path

- A domain is its **pages and their slugs** — there is no filter, no bot block, no default page (those columns were dropped in 20260925). The domain's **`status`** (`pages.domains.status`, 20260925m; `DOMAIN_STATUSES` in `src/lib/pages/types.ts`, a select on the Domains screen) comes first — but an **unverified** domain (`last_check_ok` is not true) is served as `DISABLED` no matter its stored status (`resolve` reports `DISABLED`, 20260926d), and its Status select is locked; **Verify** (`verifyDomain`) OK sets `last_check_ok` and `status = ACTIVE`, so the domain goes live, and a failed verify leaves it disabled: `ACTIVE` = the gate below; `DISABLED` = 404 for every slug (the domain serves nothing, the rules don't run); `LOCKED` = the rules still run (they mark the log), but no slug is allowed — a clean click always gets the domain's page, never the funnel; `UNLOCKED` = the rules are ignored and every slug is allowed — any click goes straight to the sub1's `[F…]` funnel (404 when the token is missing or the funnel has no live page; the domain serves funnels only). On `ACTIVE`, every request goes through the **gate** (`server/src/rules.php`, tested in `server/tests/rules.test.php`), on every path:
  1. **Rules walk** (`position` order): the first rule whose conditions all match marks the click with its **label** and it gets the domain's page **at the requested slug** (404 when no page has it).
  2. **Clean click** (no rule matched) on an **allowed slug** (`/` or one of `pages.domains.gate_slugs`) → the funnel named in the **`sub1`**'s `[F…]` token (`gate_funnel_code`: `[F23]` → F23); its A/B test (weights live in `pages.funnels.site`) picks the page, sticky in `dop_pg`.
  3. Clean, no `[F…]` token, or a slug that isn't allowed → the domain's page at the requested slug (404).
  The hit records why a click didn't go to the funnel in `pages.hits.gate_reason` (`GATE_REASONS` in `rules.php`): `slug_not_allowed`, `no_funnel_token` (no sub1, or no `[F…]` in it), `funnel_not_live` (the `[F…]` funnel has no live page — the gate data only carries funnels with one, so an unknown code is the same; the code is in `hits.funnel`), or the domain's status — `domain_disabled`, `domain_locked`, `domain_unlocked`. The Logs show it in the Reason column (muted) when no rule matched.
  The **allowed slugs are the whole `gate_slugs` list** — `/` is just one of them (20260925o), not an extra: a new domain starts with `["/"]`, and taking `/` out of the Traffic gate keeps clean clicks on the root on the safe page. The database check rejects duplicates and canonicalizes the order (`/` first).
- **Rules** (`pages.rules`, screen `/rules`, menu "Rules") DETECT bad traffic, never route: `name`, `label` (a dropdown: `RULE_LABELS` = Bot or Suspicious, in `src/lib/pages/rules-types.ts`, checked by the action), `reason` (why it flags the click, up to 200 characters, optional), free `tags` (shown as **Flow** on the screen), `conditions`, `position`, `is_active`. The conditions are the hit log's fields, every one optional: `sub1`/`sub11` (exact, case-insensitive), **`param`** (any URL parameter: `{name, equals|contains|present|not_equals|absent_or_equals}`), the base dimensions (`src/lib/pages/conditions.ts` ⇄ `server/src/conditions.php`; their per-parameter `query` map takes `present|absent|empty|{equals}` — `empty` = absent or no value) and a **User-Agent regex** (case-insensitive, `user_agent_mode: block` inverts — only rules have `sub1`/`sub11`/`param`/`user_agent`/`prefetch`), and **`prefetch: true`** (20260928a): only a request loaded ahead of a click (`request_is_prefetch` in `server/src/http.php`: `X-Moz`, `Sec-Purpose` or `Purpose` says prefetch — TikTok's Android app fetches the landing page while the ad shows in the feed; most are never clicked, and when one is, the app usually asks for the page again but sometimes shows the prefetched copy, so a rule that catches prefetches shows that visitor the safe page). In the form, the conditions are a list built with **+ Add condition** (User-Agent, Prefetch, IP, ASN, Hostname, URL parameter — repeatable; `contains` posts as the rule's single `param`, the rest as `query` —, Country, Language, Device, Referrer — sub1/sub11 are just URL parameters there; an old `sub1`/`sub11` condition opens as one); every row is required and posts the same fields `parseRuleConditionsForm` reads, so the stored JSON didn't change. **Nothing is detected in code** — a bot is only a bot because a rule says so. Writes only through `pages.rule_save` / `rule_delete` / `rule_move`. **The walk is two-stage: Bot rules run first, Suspicious rules last** — a Suspicious rule never shields a bot (and the checkpoint below only ever flags what the request stage didn't catch).
- **The device checkpoint — the Suspicious stage, in the browser** (`server/src/eval.php`, tested in `server/tests/eval.test.php`; the gate's `eval_rules`, 20261001a): what only a browser knows (a real touchscreen, the pointer kind, WebGL, automation hooks) the request can't say. When ≥1 **Suspicious** rule is active the resolve's gate carries them as `eval_rules`, and a clean click on its way to the funnel **that a Suspicious rule is still after** (`eval_checkpoint_applies`: its sub ids, URL parameters, base conditions, `eval_cookie`, and whatever signals a previous checkpoint stored — a sub11 no rule names skips it entirely) first gets a minimal, uncacheable page (no ETag, every response 200, hit logged as `SERVE · GATE · EVAL` — never a funnel/safe view). Its script collects the beacon's capability signals and POSTs them, with the URL's sub ids, to `/_dop/eval`; the server walks the eval rules with what IT can decide (the request's data; signals stored by older servers — `cache/eval/`, 1 day — are still read for a `dop_ev=<key>` cookie) and answers either the matched rules or the signal keys it still needs (`need`), which the script evaluates against the fresh signals and POSTs back (`ev`). The reload carries `?dop_rules=<names>`; the gate replays them (`eval_suspicious_rules`, only names that ARE eval rules — the parameter is never trusted) as the SAME detection a server-side match would log, and the click takes the safe page. A passed checkpoint sets `dop_ev=ok` (1 h) and the reload goes to the funnel — ONE `dop_ev` per response (`eval_response_cookie`: a second one replaces the first in the browser; the signals key used to follow `ok` and win, so a funnel's step switch got the checkpoint again and fell back to the first step — 02/10). The checkpoint page keeps `dop_step` (app.php), so a step switch that meets it still gets the step asked for after the POST. A prefetch skips the checkpoint (safe page, `SERVE · GATE-SAFE · EVAL-PREFETCH`). A browser without JS stays on the blank page — the checkpoint is a challenge too. The signal conditions (the rule form's "Device signals" section, `signal_*`/`eval_cookie` fields ⇄ `EVAL_OWN_CONDITIONS`): `touch` (0/1 = a touchscreen), `mobile_hint` (userAgentData.mobile), `pointer` (coarse/fine/none), `webdriver`, `automation`, `gl_software`, `platform` (contained), and `eval_cookie: "absent"` (the visitor never passed — catches a replayed funnel URL right in the walk, no page needed). E.g. `sub11=Taboola` + `devices=[mobile]` + `touch=0` flags an emulator/desktop posing as a phone. An undecidable signal never confirms a bot (unknown = no match; the browser is asked for it).
- **Which rule caught a hit, and the Rules screen's numbers** (20260928c–e): `pages.hits.rule_id` (no FK) is filled on insert by the `hits_set_rule` trigger — the server still sends only the rule's name/label/reason/tags, and `pages.hit_rule_id` picks the only rule with that name, else the only one with the same name, label, reason and tags (two rules may share a name); the hits from before were backfilled, only deleted rules' hits have none. It's recorded when the click happens, so renaming a rule keeps its numbers. The Rules screen has the Dashboard's periods (`?range=`, `RANGES` in `dashboard-filters.ts`) and a **Blocked** column (`pages.rule_stats`: per rule, the clicks it caught and the distinct IPs; www entry redirects not counted — the same click comes back on the bare domain) with a last **Passed** row (the clicks that passed the gate: `SERVE · GATE` with a 200, as the Dashboard counts them). Each number links to the Logs: a rule to `?rule=<id>` (the Logs' Rule select takes a label choice or one rule, grouped under "Rules"), Passed to `?funnel=sent`.
- **Every Bot rule that matches, not only the first** (20261002a): the gate serves on the first match (Bot stage, then Suspicious), so `rule`/`rule_label` only name the winner. `pages.hits.rule_matches` (jsonb, `[{name,label,reason,tags}]`) lists EVERY active Bot rule whose conditions match the request, to compare rules and see their overlap — logging only, the serving decision doesn't change. `gate_bot_rules_matched` (`server/src/rules.php`) runs in `log_hit` AFTER the response and after the ASN/hostname lookups (the hostname Bot rules reuse the cached PTR: no new DNS), and goes in through `log_hit_net` (`p_rule_matches`). NULL = no Bot rule matched (clicks that passed, or were caught by a Suspicious rule); the serving rule is always in the set. **Suspicious rules are not evaluated**: their device-signal conditions only exist after the browser checkpoint (`eval.php`). The Logs' **All Bot rules** column shows it (the rule that served is outlined).
- **Platform = sub11** (20260928b): `pages.hits.platform` is the click's `sub11`, lowercased, filled on insert by the `hits_set_platform` trigger (`pages.hit_platform`). The Dashboard (a select next to the domain; `hit_stats`/`hit_series`/`recent_hits` take `p_platforms`) and the Logs (`?platform=`) filter by it; the options come from `pages.hit_platforms` (the platforms with hits in the period / the last 30 days), labeled by `platformLabel`.
- **The funnel page and the VSL video the visitor got** (`server/src/beacon.php`, `server/src/vsl.php`): a funnel's page served by the gate sets the `page_id` cookie (the served page's id — the split's pick; 1 day); a response that drew a VSL video sets the `video_id` cookie (30 days), and a funnel page that drew none deletes an older one — so it always speaks for the page it came with (dot.js reads it for its page_view and video events). dot.js sends the page's id (a uuid) as `page_id` in every event, from its own URL first (`?page_id=`: the loader adds it to the tracker's URL, and a page's own tracker tag gets it by writing `page_id={{page_id}}` — `page_id_placeholder_apply`: the funnel page the gate served, empty on any other route; the id goes into the ETag), otherwise from the cookie. dot.js takes the VSL video the same way — `?video_id=` first (the loader adds it to the tracker's URL when the response drew a video; a page's own tag writes `video_id={{video_id}}`), otherwise the `video_id` cookie. Both cookies are not HttpOnly (the page's own trackers may read them) — the server's click event to dot carries both (below).
- **The browser's notices live on the hit** (there is no `hit_loads` table) and **only a funnel's page served by the gate carries them** (`beacon_applies`: match_type `GATE`, HTML): the safe page (GATE-SAFE) and any other route go without the script and without the `dop_v` visit cookie, so their hits show — in Loaded/Interaction; the Funnel screen's numbers (`pages.funnel_page_stats`) count the funnel page served by the gate (its own id) plus the domain copies logged before. `/_dop/l` (`beacon.php`) marks the visit's hit by `visit_id` (the script reads it from the `dop_v` cookie once, at load, and sends it with every notice as "v=", so a later page's new cookie can't take this page's notices; the cookie isn't HttpOnly) — `loaded_at`/`load_ms` (load event), `interacted_at`/`interaction`/`interaction_ms` (the FIRST real interaction: `mouse` moved or pressed, `scroll` wheel, `touch`, `key` — only events the browser made, `isTrusted`; shown in the Logs' Interaction column) `clicked_at` (a click also counts as loaded) and `duration_ms` (how long the page stayed open: the script sends "d=<ms>" every time the page is hidden or left — visibilitychange/pagehide —, the longest report wins; the Logs' Time on page column) — through `log_load`/`log_interact`/`log_click`/`log_duration`, which return false when the hit isn't written yet: the server retries after 1, 2 and 4 s (`beacon_record`, after the response). Every notice may also carry "sg=\<json\>", the visit's **device/behavior signals** (`pages.hits.signals`, via `log_signals`; top-level merge, newest key wins; INFORMATIONAL ONLY — nothing is blocked from them): the capabilities at load (webdriver, platform, touch points, cores, memory, languages/plugins counts, primary language `lng`, screen/viewport + DPR, pointer fine/coarse, hover, window.chrome, userAgentData, the phone's model `mdl` — the Sec-CH-UA-Model client hint, since Chrome on Android sends "K" in the User-Agent —, cookies, plus headless/automation tells collected on the load event so they never delay paint — `aut` = how many automation artifacts, chromedriver `cdc_`/Playwright/Puppeteer/Selenium/phantom hooks, and the WebGL renderer `gl` with `glsw` = 1 when it is software: SwiftShader/llvmpipe/Mesa/no GL) and the session's trusted event counts when hidden/left (mm, md, wh, sc, ts, ky, ck — 0 on a device that has the pointer means nobody drove it — plus the mouse trajectory `str`/`dc`/`tp`: how straight the path is 0-100, direction changes, teleports — and the **read depth** `sd`/`ph`: the deepest the bottom of the screen got, % of the page's height, the first screen counting without a scroll, and that height in px; the scroller is the window or an element as tall as most of the screen, and a page that scrolls nothing measurable reports no `sd` — the Logs' **Read** column). The Logs' **Model** column (`src/lib/device-model.ts`) names the phone: an Apple identifier in the User-Agent (Facebook's `FBDV/iPhone14,5`, Instagram's) or Android's model token (Samsung codes get the Galaxy name), else `mdl`, else an iPhone estimated from the screen size (`~`; Display Zoom makes a bigger iPhone read as a smaller one). The Logs' Signals column derives the hints (webdriver, automation, software GL, no mouse/touch/scroll, straight mouse, headless?) and shows the counts and the trajectory, full JSON on hover. To make that rare, the hit is written right after the response with what the per-IP cache already knows (`log_hit` returns its id) and the ASN/hostname lookups go after, into the same hit (`log_hit_net`).
- **Unique clicks**: `pages.hits.is_unique` is set by a BEFORE INSERT trigger (`pages.hits_set_unique`, so any server's `log_hit` gets it): true = no hit with the same IP and the same User-Agent on the same domain (`domain_id`; the host when unregistered) in the 30 days before, false = a repeat; redirects are NULL and don't count as an earlier hit (www → bare domain is the same click). Index `(ip, created_at)`. The Logs' Unique column shows it.
- **IP, ASN and hostname** conditions (`ips` IPs/CIDR ranges, `asns` AS numbers, `hostname` a regex on the reverse DNS; each with `_mode: block` to invert; validated by `pages.rules_check`): the server checks the IP first and the ASN/hostname LAST, only when everything else in the rule matched. **The ASN (and its name) comes from a local table** (`server/src/netdb.php`, tested in `server/tests/netdb.test.php`): iptoasn.com's ranges (public domain), rebuilt once a day after a response by one process into `cache/netdb/` (binary, sorted: a lookup is a binary search, ~30 µs, no network); without a usable table (missing, or over a week old) it falls back to Team Cymru over DNS. The same table gives the **country when Cloudflare's CF-IPCountry is missing** (the network's country — Cloudflare's header always wins). The hostname stays a DNS lookup (`server/src/netinfo.php`, tested in `server/tests/netinfo.test.php`: its own UDP DNS client with a timeout, `NETINFO_RULE_TIMEOUT_MS` = 400 ms by default before the response, 1.5 s for the log after it; the answer is cached per IP for a day, a failure for 10 minutes but retried by a caller that can wait longer). A lookup that fails makes the condition not match: a click is never flagged on a guess. The log reuses the same lookups (`hits.asn` / `as_name` / `hostname`).
- The gate's data comes **fused in `pages.resolve`'s `gate` column** (the domain's `status` + rules in order + `gate_slugs` + every funnel's code + live split + VSL), cached with the routes and decided **per request** in PHP (no Supabase per click). The hit records the detection (`pages.hits.rule_label` / `rule` / `rule_reason` / `rule_tags`; the Logs screen shows them in its Rule, Flow and Reason columns, and filters by Flow — `?flow=<tag>`, a `rule_tags` containment, options from the rules' tags; its Language column lists `pages.hits.accept_language` by preference, without the q weights, via `src/lib/accept-language.ts`) and, for a clean click, the funnel it went to (`pages.hits.funnel`).
- **Click events to dayone-main's tracker** (`server/src/dot.php`, tested in `server/tests/dot.test.php`): every page request whose URL carries a platform click id (`CLICK_ID_PARAMS`: ext_click_id, gclid, wbraid, gbraid, dclid, fbclid, ttclid, tclid, tbclid, tblci, snclid, sccid, msclkid, twclid, li_fat_id, epik, rdt_cid, qclid, obclid, dicbo, yclid, nbclid, kwai_click_id, click_id, clickid, ref_id — case-insensitive) is POSTed, after the response and after the hit is logged, to the `dot` edge function (`DOT_URL`, default `https://cdn.dayone.click/functions/v1/dot`) as event `click`, in the same shape as the sites' own click events in `tracking.dot_events`: `site` (host), `lander` (path), `url`, `referrer`, `ip`, `user_agent`, `timestamp`, `sub1`…`sub11` (dot maps them), `cid` (= `cmpid`), `rtkcid`, `ext_click_id` (the first click id, in dot's order), `wbraid`/`gbraid`, `dotid` (the dot.js cookie or `?dotid=`, when well formed) and `_metadata` (headers, cookies, every click id, and `dayone_pages`: hit id, decision, sent_to_funnel, funnel, page, video, gate reason, rule label/name/reason/tags, country, device, ASN, hostname), plus `page_id` (the funnel page the gate served — dot's `page_id` column, mapped by dayone-main's dot function and `tracking.process_dot_queue` since its migration 20260928_dot_events_page_id) and `video_id` (the VSL video this response drew — dot's `video_id` column). A real click on a **pre-lander** page — a slug outside `PRE_LANDER_STANDARD_SLUGS` (`/`, `/contact`, `/disclaimer`, `/privacy-policy`, `/refund-policy`, `/shipping`, `/terms-of-use`), served **200** (not a funnel page the gate served — that one has dot.js) and not caught by a rule — also gets a **second server-side event, a `page_view`** with the same fields marked **`origin: pre_lander`** (`dot_pre_lander_origin` / `dot_page_view`): the pre-lander page has no dot.js (nothing is added to its HTML), so the server sends the page_view itself (dot fills its `pre_lander` column from `origin` + `lander`). The **click event is unchanged** (no origin); a rule-caught click, the home and the legal pages send only the click. A duplicate page_view (e.g. a stepped page that also carries dot.js) is harmless — dot doesn't count the server-side page_view in its funnel maths. Bots and rule-caught clicks are sent too (the rule is in the metadata); the www entry redirect isn't (the same click comes back on the bare domain), nor is a prefetch (`$req->prefetch`: not a click, and `tracking.process_dot_queue` keeps only the FIRST click event of a click id, so a prefetch sent would stand for the real click that follows it). The timeout (`DOT_TIMEOUT`, 8 s) is above dot's own budget for its database write (4 s); a click dot didn't queue — no answer, or a 5xx (dot's 503 = its write failed) — is sent again 1 s and 4 s later (`DOT_TRY_WAITS`: the Supabase blips seen lasted up to 5 s; a click sent twice is harmless, dot keeps the first), and one that still failed is **not lost**: it waits in `cache/dot-spool.jsonl` (with its own timestamp) and goes again after a later response, at most once a minute (`dot_spool_replay`: stops at the first one dot still can't take, gives up after a day or on a 4xx — only those go to the log). dot's outages seen so far (PGRST002 while PostgREST reloads its schema cache, the database out of connections) lasted up to 20 minutes. `DOT_CLICKS=0` turns it off — the test runner sets it: tests and local runs never feed the real tracker.

## Template variation

- When copying a template to a domain you can ask for a **visual variation** (`src/lib/pages/variation.ts`): colors, fonts, corners/shadows and spacing change from a seed, only in the values of `<style>`/`style=""`/SVG colors — never in selectors, `@font-face`, images or external CSS (which only gets the body font on top). Preview before saving (`previewTemplateVariation` → `copyTemplateVariation` → `pages.domain_page_add`).
- With a **copy angle**, the texts are rewritten by AI (`src/lib/pages/copy-angle.ts`): Kimi (Moonshot API, OpenAI-compatible, JSON mode) when its key is in the system; otherwise Claude (`@anthropic-ai/sdk`, `claude-opus-5`, streaming, structured output, `fallbacks: "default"`) when there is `ANTHROPIC_API_KEY`. **The Kimi key lives in the system, not in `.env`**: encrypted in Supabase Vault through `pages.ai_secret_set/get/status` (closed list of names — the Vault is shared with dayone-main), edited in Settings (`src/lib/ai-settings.ts`); the model is fixed in the code (`AI_MODEL` = `kimi-k3`) — there is no settings table. Never send the key to the browser (the screen only gets its last 4 characters). Only the text between tags goes to the model and comes back to the same place; a piece that loses a `{{placeholder}}` stays as it was. The prompt forbids inventing facts, promises, testimonials and claims. Without either key, only the visual variation works. No key ever goes into the repo (it is public).

## Funnel (the steps of a slug)

- Always the same three steps, in this order: **Pre Lander** (`presell`) → **Lander** (`main`) → **Backredirect**. No other kinds, free names or extra steps. A slug without sections is just the Lander.
- A step **without code** (no section, or an empty/comment-only section) is **inactive** and never shows. The visitor first sees: 1) the Pre Lander, if active; 2) otherwise the Lander. `#next-step` goes from the Pre Lander to the Lander; the Backredirect only shows on back/exit intent.
- **One step per response, always** (`server/src/funnel.php`): the delivery server cuts a page with steps down to the current one — there is no "browser mode" (the editor has no Step switching choice; an old `<body data-dop-funnel>` is ignored and dropped on the next save) —, so a step's scripts (a VSL player's autoplay, say) never run behind another step. Moving on sets `dop_step` and reloads the same URL; the response that used the cookie deletes it (a refresh or a later visit starts at the first step), and that request's hit is `SERVE · GATE · STEP` — the same visit: the Funnel screen (`funnel_page_stats`) doesn't count it as a view, only its clicks out; the Logs' "sent to funnel" filter includes it (`FUNNEL_DECISIONS`). dot still gets its click (`tracking.process_dot_queue` keeps only the first click event of a click id, so it's dropped there).
- The rule is the same in three places — change one, change the others: `src/lib/pages/subpages.ts` (editor), `src/lib/pages/runtime.ts` (the preview, which has every section) and `server/src/funnel.php` (the delivery, tested in `server/tests/funnel.test.php`). Without a DOM (dashboard server), the reader is `src/lib/pages/funnel-scan.ts`, equal to PHP's `funnel_sections`.
- **The funnel's tracker, per step** (`server/src/track.php`, tested in `server/tests/track.test.php`): **one script, `/_dop/dot.js`, sent as the step it's on** — `?origin=pre_lander` on the Pre Lander, `?origin=lander` on the Lander (`TRACK_ORIGINS`; the Backredirect has none; `pre_dot.js` is gone). The only difference by origin is when the page_view goes: `lander` at once (the first request, as before), `pre_lander` once the page has loaded (window `load`, 10 s cap, `pagehide` net — as pre_dot.js did, so the Pre Lander numbers keep the same yardstick); everything else is the same code (attribution, dotid, `page_id`, retries, video events whenever it has a `video_id`). The server sends one step per response, so it puts **the served step's tracker straight in the `<head>`** (`track_inject`, right after `<head>` — the earliest spot, so the page_view goes out and the player is bound before the VSL is ready; no loader): **only a funnel page the gate served (`beacon_applies`) gets it** — as the served step's `kind` (`funnel_apply`) when the page has steps, and **a funnel page without steps is all Lander** (`dot.js?origin=lander`). A page with steps served outside the gate (a domain/safe page that happens to be built as a funnel) gets no tracker; a real click on it, when it's a pre-lander slug, is marked server-side instead (the `page_view` with `origin: pre_lander`, below). A page that already has a `dot.js` or `pre_dot.js` tag of its own (any host, relative included — `track_has_own_tag`) gets none, which would run twice; nobody has to remember the tag. **The VSL marks are VTurb's numbers** (compared with `vturb.analytics_hourly`): `video_play` = VTurb "started" (the muted smart autoplay counts, as in its play rate), `video_watch` every 5 s (dot keeps the max), `video_pitch` from VTurb's own `pitch:time` (only after a real play; the config's pitchTime as a fallback, never during `inSmartAutoPlay`), `video_click` from VTurb's `analytics:exited-click` (its CTAs live inside the player) or a checkout link, as a beacon that never holds the navigation, and `video_end` from `video:ended` (VTurb "finished"); a player that was already ready when the tracker arrived is bound at once (`window.smartplayer.instances`). Every event carries **`ext_click_id`**, picked from the URL in the server's `CLICK_ID_PARAMS` order (Taboola's `tblci` included), so dot ties the browser's events to the server's click. **Nothing is lost — the outbox**: every event stays in `localStorage` (`dot_outbox`) until dot confirms it; a 5xx/429 or no answer is retried (2 s, 4 s, 8 s… every minute, for 15 minutes on the page), and the next page of the domain sends what's left (for a day) with `_delay_ms` (how long ago it happened: dot dates it without trusting the device's clock); only the latest pending `video_watch` of a video is kept; sending twice is harmless (dot keeps one). **The read depth goes to dot too**: `scroll_depth` (the same measure as the beacon's `sd` — the deepest the bottom of the screen got, % of the step's page) is sent as a beacon when the page is hidden or left, only when it grew; dot doesn't store it as a row — `tracking.process_dot_queue` raises the `scroll_depth` of the step's `page_view` (same origin and click id, the max wins; applied after the batch's INSERT since dayone-main's 20261002n, so a visitor who leaves in seconds keeps theirs), and the outbox keeps only the latest pending one of a page and step (the next page re-sends it). **The tracker is first party**: this server serves it on the funnel's own domain at `/_dop/dot.js` (`TRACKER_FILES`, `handle_tracker` — no hit, no Supabase), and its URL has `?v=<content hash>` (cached for good; a changed tracker is a new URL), plus `&page_id=<the page's id>` on a funnel page the gate served and `&video_id=<the drawn video>` when the response drew one — **only when the served step's own code has `{{video_id}}`** (vsl.php, below), on whichever step drew it. It sends to dayone-main's dot edge function; `dot.js` takes the VSL video from its URL (`&video_id=`) or the `video_id` cookie (never from the player): a page with no video drawn reports no video. Each step is its own load (the server sends one step per response); the loader's `dop:pageshow` listener only matters without the server. Injected only on the real delivery (never in the dashboard preview). `track_etag()` (`TRACK_ETAG` + the tracker's URLs) goes into the ETag of a funnel page the gate served, also in `serve_slug`'s 304 shortcut for pages without steps — so a browser holding a copy from before revalidates.
- **Funnel screen** (`/funnels`): the list of **dayone-main** funnels (`public.funnels`, codes F1, F2…), read only through `pages.main_funnels()` — the dashboard never writes to `public`. Each funnel expands (collapsed by default) and shows its pages (`pages.funnels` row, created on first use by `pages.funnel_for`; `main_funnel_id` UNIQUE, ON DELETE SET NULL), one row per page (pages of a funnel that disappeared from dayone-main show in a last row). Funnels are not on the Templates screen. "New page" is the same flow as "Create template" (`CreatePageForm` with `funnel`: copy from template/link/HTML, placeholder question, from scratch = Pre Lander + Lander) plus **Copy from another funnel** (a page of any funnel, this one included — redirects aren't pages and aren't listed; source `funnel_page`), and the page is created by `funnel_page_add`. "New page" also offers **Redirect** (funnels only): a funnel entry that 302s instead of serving a page — a `pages.pages` FUNNEL page whose `/` slug has `content_type = 'text/x-redirect'` and content = a destination URL TEMPLATE (e.g. `https://offer.com/?utm_campaign={sub1}`). It lives in the split like a page (its own weight) but is **always published** — it has no content to review; it is paused with 0% — created/edited with `createFunnelRedirect`/`saveFunnelRedirect` (reusing `funnel_page_add`/`funnel_page_save`). On the Funnel screen a page row shows a page icon, its status and Edit; a redirect row shows a link icon and its destination, no status and no Edit — clicking it opens its form (name, URL, Delete; saving a redirect that was still a draft publishes it and it joins the split). Every row has **Delete** (`removeFunnelPage`: the entry goes, the published ones left are rescaled to 100). `resolve` puts the template in the split entry as `redirect` and `funnel_pages_summary` returns it; the delivery server (`server/src/funnel.php` `funnel_redirect_url`, tested in `server/tests/redirect.test.php`) fills each `{name}` from the visit's query (URL-encoded; missing = empty) and 302s — ONLY what the template names goes, nothing else is appended. A funnel with no published page or redirect with a share above 0 (nowhere to send a click) shows a red **!** before its code. The Funnel screen has no folders.
- **Funnel tabs**: an expanded funnel has two tabs, **Pages** (default: its pages and their A/B test) and **VSLs** (its VTurb A/B test, below, loaded only when the tab opens). There are no tabs at the top of the screen and no `?tab`. In both tabs the % is the first column and the rows go highest % first (by the saved %, so rows don't move while typing). `pages.funnels` has a row for every dayone-main funnel, with `code` and `name`, kept by `pages.funnels_sync()` (called when the screen loads).
- **VSL split of the funnel** (a new scope, built only in the `pages` schema — nothing of dayone-main is changed): **the split is ours, never VTurb's — the dashboard sends nothing to VTurb.** `pages.funnels.vsl` IS the split: `{ "<VTurb player id>": { "weight": 0-100, "name": "…" } }` (shares add up to 100, checked by a trigger; 0 = paused), `vsl_updated_at` its version. The VSLs tab saves through `pages.funnel_vsl_set(p_funnel, p_vsl, p_expected)`: only over the version the screen loaded (NULL back otherwise: the screen reloads and asks to redo the change — never raise 40001 from a function PostgREST calls: it retries it in a loop); a video can join at 0% (paused: never drawn); then the domains with the funnel get their cache purged. **Delivery**: `pages.resolve` sends the served page's funnel videos with a share above 0 (`vsl`: `[{ id, weight }]`); the server (`server/src/vsl.php`, tested in `server/tests/vsl.test.php`) draws one per visitor by weight, sticky in the `dop_vsl` cookie, and puts it in the page's VTurb player marked as A/B test (`data-vturb-kind="ab-test"`: `data-vturb-id` = the video, kind emptied, so the player loads that video directly); players with a fixed video are left alone. **`{{video_id}}`** takes the same draw in any page (pasted HTML included): written where a VTurb video id goes — e.g. VTurb's single-video embed, `<vturb-smartplayer id="vid-{{video_id}}">` and `…/players/{{video_id}}/v4/player.js` — it becomes the drawn video (empty with no video in the split). **The draw is the served step's**: only a `{{video_id}}` in the step's own code (the `<body>` after the other steps are cut; a page without steps is all Lander) draws — the `<head>` is every step's, so a `{{video_id}}` only there (a player preload, a tracker tag) draws nothing and becomes empty (`vsl_step_code`). So a Pre Lander → VSL page draws only when the visitor reaches the VSL, even with the preload in the `<head>`, and the video goes to dot (tracker URL, `video_id` cookie, click event) only from the step that drew it. It's filled by `vsl.php`, not with the domain's data (the gate's funnel route carries no domain placeholders). The page builder keeps its HTML inside a JSON string, so the player is found plain or JSON-escaped (`\"`). The video goes into the ETag and the response varies by Cookie. The tab loads in ONE call, `pages.funnel_vsl_panel()`: the split plus only the dayone-main VSLs that can match its videos (by the player id the pipeline recorded, otherwise by name without `.mp4`); "+ Add VSL" lists, as soon as it opens, the finished VSLs of the funnel's niche and language (`pages.main_vsls_search(p_main_funnel, …)`, like dayone-main's A/B picker: niche by `public.niches` code → value, language = the region after the slash with GE read as DE; a niche without a code, like OT, lists nothing), narrowed by the typed words, filtered and limited in the database (the VSL's video = the first VTurb player id the pipeline recorded) or takes a pasted VTurb video id, looked up in dayone-main's copy of the VTurb library (`pages.vturb_player_find()`). Never read every VSL to show a few.
- **A/B test between the pages of a funnel**: each page has its share (`weight` in `pages.funnels.site`, 0–100; 0 = paused), read LIVE by the copies (not copied). **Only a PUBLISHED page or redirect gets traffic, so only those hold a share, and they add up to 100** (`src/lib/pages/traffic.ts` + `funnel-weights.ts`). On the screen the shares are typed freely in each row's field and saved together with **Save**, which only works when they add up to exactly 100 (`saveFunnelShares` checks it again, and that the set of published entries didn't change meanwhile); "Split evenly" and "Reset" only fill the fields. A page **joins** the split with 100/n when it is published (the others shrink) and **leaves** it when it stops being published (the others are rescaled); a deleted page gives its share back. A draft shows — and has no % field; its stored value is left alone (a domain copy may still read it live). The screen shows the published pages' shares rescaled to 100 (the proportions the server uses). "Copy from another template" and "Copy from another funnel" create the funnel page **published** (it joins); the other sources start as a draft. The Funnel screen no longer copies a funnel to a domain (`domain_funnel_copy` stays in the database for the copies that exist; a page removed from the funnel gets 0% in them). On the domain, when the route resolves to a copy of a funnel page and there are other copies of the same funnel at the same path, `pages.resolve` returns `split` and the server (`split_pick` in `funnel.php`) picks one per visitor by weight, sticky in the `dop_pg` cookie; the hit records the page served. Numbers per funnel page (`pages.funnel_page_stats`): real loads of the copies (`hits.loaded_at`) and how many clicked out (`hits.clicked_at`, the load beacon sends `c=1`). Changing a weight purges the cache of the domains that have the funnel.
- **A/B test = samples of a step**: sibling sections of the same kind ("Lander A", "Lander B"…), each with `data-dop-weight` (0–100; 0 = paused). The delivery server picks (`ab_apply` in `funnel.php`), one per step and visitor, sticky in the `dop_ab` cookie (`<visitor>:<ids>`), and serves ONLY the picked one (in any mode); the combination goes into the ETag and the response varies by Cookie. Without the server (preview), the first active sample wins.
- Samples have no per-sample numbers (`pages.funnel_events` and `/_dop/e` were dropped in 20260924q); the numbers are per funnel page (above).

## Frontend

- **Display time zone: New York** (`America/New_York`), through the `APP_TZ` constant of `src/lib/time-zone.ts`. Every `Intl.DateTimeFormat`/`toLocale*` that shows a date or time passes `timeZone: APP_TZ`; never depend on the server's or the browser's time zone.
- **NY has daylight saving time**: a local day has 23, 24 or 25 hours. "Midnight N days ago" is `localMidnight(now, N)`, never `midnight - N * 24h`.
