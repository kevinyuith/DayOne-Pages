# Project rules

## Language: everything in English

- **The whole repo is in English**: code, identifiers, comments (TS, PHP, SQL), docs, commit messages, test names, log messages, routes and query params (`/templates`, `/domains`, `/funnels`, `/settings`, `?folder=`, `?days=`). The old Portuguese addresses (`/paginas`, `/dominios`, `/funil`, `/configuracoes`) only redirect, in `next.config.ts`.
- **Database** (Supabase, schema `pages`): tables, columns, functions, parameters, indexes, constraints, CHECK/enum values, `COMMENT ON`, `RAISE` messages and comments. When a database error reaches the screen, the action translates it by error code (e.g. `23514`) instead of showing the raw message.
- **UI**: dashboard (menu, titles, buttons, confirmations, action/lib error messages, labels), `<html lang="en">`, dates and numbers in `en-US`, and the pages the PHP server returns to visitors (403/410/451/503). The dashboard has `translate="no"` on `<html>` so the browser does not translate it.
- The only other languages are per-visitor-language data: the month/language-name tables of `{{date}}`/`{{language}}` (`placeholders.ts` = `placeholders.php`) and the legal suffixes of `company.name` (LLC, Ltda, GmbH…).
- **No explanatory text on screens**: the header is only the title (`PageHeader` has no description) and there are no footnotes explaining the screen or the metrics. Labels, empty states and error messages stay.
- **Time in UTC**: every date is `timestamptz` (never `timestamp` without time zone) and the database runs in UTC. Functions take and return instants and never convert time zones: no `AT TIME ZONE` nor fixed zones in SQL. Grouping by local day is the frontend's job.

## Pages: one table for every page

- **Every page lives in `pages.pages`**, its slugs and HTML included, in the `slugs` column: `{ "/path": { title, content, content_type, is_active, content_hash, created_at, updated_at } }` (`content_hash` = sha256 of the HTML, filled by a trigger). `scope` says what it is: `TEMPLATE` (the Page templates screen, `/templates`; never served, never FUNNEL), `DOMAIN` (served by one domain) or `FUNNEL` (a page of a funnel). There is no `page_slugs` table. **Never `select("*")` on `pages`** (it carries the HTML): read through `pages.pages_summary` / `domain_pages_summary` / `funnel_pages_summary`, and one slug's HTML through `page_slug_get` / `domain_slug_get` / `funnel_slug_get`.
- **`pages.domains.site` and `pages.funnels.site` are only lists**: `{ "<page id>": {} }` and `{ "<page id>": { "weight": 50 } }`. A page is listed by exactly one domain or funnel (triggers); removing it from the list deletes the row, and deleting the domain or funnel deletes its pages. `default_page_id`, `filter_pass_page_id` and `filter_fail_page_id` must be pages in the domain's list (triggers). A domain serves, in order: bot block (`block_bots`, 403) → filter (pass/fail page) → default page, with the request path as the slug. There are no per-path routes (`domain_routes` was dropped in 20260924q).
- **Writes only through the functions**: `page_save` and `page_slug_create/rename/set_active/delete` for any page (they lock the row and use optimistic concurrency on `updated_at`; the last slug of a page is not deleted), the `domain_*` wrappers (check the page belongs to the domain) and the `funnel_*` wrappers (same for the funnel). Templates are created with a plain insert (`scope: "TEMPLATE"`, `slugs`).
- **Domain pages are copies**: of a template (`domain_page_copy`, `domain_page_add` for a variation) or of the pages of a funnel (`domain_funnel_copy`), recorded in `template_id` / `funnel_page_id` + `funnel_id`. From then on they are independent: editing the copy does not change the source and vice versa (the funnel A/B share is the exception: it is read live). "Change template" replaces the copy (`domain_page_replace`, same id, edits lost).
- **One editor** (`src/components/editor/page-editor.tsx`), with actions and links coming from the route: template at `/templates/[id]/edit?slug=/path`, funnel page at `/funnels/[pageId]/edit?slug=/path`, domain page at `/domains/[id]/pages/[pageId]?slug=/path`. A slug's id is its path.

## Delivery server and cache

- `pages.resolve(host, path, key, p_with_content => false)` returns only the decision (routes, conditions, A/B split) and each slug's `content_hash`; the HTML comes through `pages.content_get([{ page_id, slug }])` only for hashes that are not on disk (`cache/content/<hash>.php`, never invalidated — a hash never changes content; the cleanup removes files no route used for `STALE_MAX_AGE` + 1 day). The server re-checks the decision every `CACHE_TTL` (30 s) with SWR on (the visitor gets the stored copy; the check happens after the response). `p_with_content` defaults to `true` only for servers that are still on the old code.

## Template variation

- When copying a template to a domain you can ask for a **visual variation** (`src/lib/pages/variation.ts`): colors, fonts, corners/shadows and spacing change from a seed, only in the values of `<style>`/`style=""`/SVG colors — never in selectors, `@font-face`, images or external CSS (which only gets the body font on top). Preview before saving (`previewTemplateVariation` → `copyTemplateVariation` → `pages.domain_page_add`).
- With a **copy angle**, the texts are rewritten by AI (`src/lib/pages/copy-angle.ts`): Kimi (Moonshot API, OpenAI-compatible, JSON mode) when its key is in the system; otherwise Claude (`@anthropic-ai/sdk`, `claude-opus-5`, streaming, structured output, `fallbacks: "default"`) when there is `ANTHROPIC_API_KEY`. **The Kimi key lives in the system, not in `.env`**: encrypted in Supabase Vault through `pages.ai_secret_set/get/status` (closed list of names — the Vault is shared with dayone-main), the model in `pages.app_settings` (`ai.model`), edited in Settings (`src/lib/ai-settings.ts`). Never send the key to the browser (the screen only gets its last 4 characters). Only the text between tags goes to the model and comes back to the same place; a piece that loses a `{{placeholder}}` stays as it was. The prompt forbids inventing facts, promises, testimonials and claims. Without either key, only the visual variation works. No key ever goes into the repo (it is public).

## Placeholders `{{key}}`

- Company data in `pages.domains.placeholders`, with `company.*` keys (`llc` = legal name, `number`, `address`, `phone`, `email`; list in `src/lib/pages/placeholders.ts`). `{{company.name}}` is not stored: it is the legal name without the legal suffix (LLC, Inc., Ltda, GmbH…), by `companyName()` / `company_name()` — the same suffix list on both sides, tested by the same cases (`server/tests/company-names.json`; `npm run check:company-name` and the PHP suite). Automatic on every visit: `url`, `domain`, `slug`, `date`, `year`, `lang`, `language` — language from the visitor's Accept-Language (`en` without it), today's date in New York spelled out in that language.
- The delivery server replaces them when serving (`server/src/placeholders.php`); the dashboard does the same replacement only in the preview (in `en`). The rules and the language/month tables are the same on both sides — change one, change the other: only known keys, an empty value becomes empty text, values are HTML-escaped.
- In the editor, typing `{{` opens the placeholder list (text on the canvas, Text/Link fields of the inspector, code mode). The list comes from `PLACEHOLDER_OPTIONS`/`suggestPlaceholders`: a new placeholder is added only in `placeholders.ts`.

## Funnel (the steps of a slug)

- Always the same three steps, in this order: **Pre Lander** (`presell`) → **Lander** (`main`) → **Backredirect**. No other kinds, free names or extra steps. A slug without sections is just the Lander.
- A step **without code** (no section, or an empty/comment-only section) is **inactive** and never shows. The visitor first sees: 1) the Pre Lander, if active; 2) otherwise the Lander. `#next-step` goes from the Pre Lander to the Lander; the Backredirect only shows on back/exit intent.
- The rule is the same in three places — change one, change the others: `src/lib/pages/subpages.ts` (editor), `src/lib/pages/runtime.ts` (browser mode) and `server/src/funnel.php` (server mode, tested in `server/tests/funnel.test.php`). Without a DOM (dashboard server), the reader is `src/lib/pages/funnel-scan.ts`, equal to PHP's `funnel_sections`.
- **Funnel screen** (`/funnels`): the list of **dayone-main** funnels (`public.funnels`, codes F1, F2…), read only through `pages.main_funnels()` — the dashboard never writes to `public`. Each funnel expands (collapsed by default) and shows its pages (`pages.funnels` row, created on first use by `pages.funnel_for`; `main_funnel_id` UNIQUE, ON DELETE SET NULL), one row per page (pages of a funnel that disappeared from dayone-main show in a last row). Funnels are not on the Templates screen. "New page" is the same flow as "Create template" (`CreatePageForm` with `funnel`: copy from template/link/HTML, placeholder question, from scratch = Pre Lander + Lander), and the page is created by `funnel_page_add`. `folders.scope = 'FUNNEL'` exists in the database but the Funnel screen uses no folders.
- **Funnel tabs**: an expanded funnel has two tabs, **Pages** (default: its pages and their A/B test) and **VSLs** (its VTurb A/B test, below, loaded only when the tab opens). There are no tabs at the top of the screen and no `?tab`. In both tabs the % is the first column and the rows go highest % first (by the saved %, so rows don't move while typing). `pages.funnels` has a row for every dayone-main funnel, with `code` and `name`, kept by `pages.funnels_sync()` (called when the screen loads).
- **VTurb A/B test of the funnel's videos** (a new scope, built only in the `pages` schema — nothing of dayone-main is changed): VTurb decides which video plays. `pages.funnels.vturb_group_id` is the funnel's test in VTurb (its "comparison group"), `pages.funnels.vsl` the replica of the test: `{ "<VTurb player id>": { "weight": 0-100, "name": "…" } }`, `vsl_synced_at` when it was last read/written. The dashboard writes VTurb FIRST (`src/lib/vturb.ts`: VTurb's web-app API, GET the whole group → set `players[].traffic_percentage` and `tree` weights → PUT; the % must add up to exactly 100; a video joins the test only with a share above 0) and then saves what VTurb has (`pages.funnel_vsl_save`). Before writing, it compares VTurb's current % with the ones the screen loaded: if they differ (someone changed the test elsewhere) it writes nothing, re-reads the test into the replica and asks to redo the change. "+ Add VSL" (bottom of the funnel, like "New page" in Pages) searches the produced VSLs (`searchProducedVsls`: dayone-main, not archived; the VSL's video = the first VTurb player id the pipeline recorded) or takes a pasted VTurb video id; the video joins the test on Save, with a share above 0. The tab loads in ONE call, `pages.funnel_vsl_panel()`: the replica, only the dayone-main VSLs that can match its videos (by the player id the pipeline recorded, otherwise by name without `.mp4`) and, for funnels without a test, the VSLs linked to them; the search is `pages.main_vsls_search()` (filtered and limited in the database). Never read every VSL to show a few. The token comes from `pages.vturb_token()` — for now it only READS dayone-main's token; when this scope moves out, only that function changes. Never send the token to the browser.
- **A/B test between the pages of a funnel**: each page has its share (`weight` in `pages.funnels.site`, 0–100; 0 = paused), edited on its row and read LIVE by the copies (not copied). **A funnel's shares always add up to 100** (`src/lib/pages/traffic.ts`, the same math on the screen and in the action): changing one spreads the rest among the others in the proportion they had; a new page comes in with 100/n and the others shrink; a deleted page gives its share back. "Copy funnel to domain" (`domain_funnel_copy`) copies every non-archived page as published; a page removed from the funnel gets 0% in the copies. On the domain, when the route resolves to a copy of a funnel page and there are other copies of the same funnel at the same path, `pages.resolve` returns `split` and the server (`split_pick` in `funnel.php`) picks one per visitor by weight, sticky in the `dop_pg` cookie; the hit records the page served. Numbers per funnel page (`pages.funnel_page_stats`): real loads of the copies (`hit_loads`) and how many clicked out (`hit_loads.clicked_at`, the load beacon sends `c=1`). Changing a weight purges the cache of the domains that have the funnel.
- **A/B test = samples of a step**: sibling sections of the same kind ("Lander A", "Lander B"…), each with `data-dop-weight` (0–100; 0 = paused). The delivery server picks (`ab_apply` in `funnel.php`), one per step and visitor, sticky in the `dop_ab` cookie (`<visitor>:<ids>`), and serves ONLY the picked one (in any mode); the combination goes into the ETag and the response varies by Cookie. Without the server (preview), the first active sample wins.
- Samples have no per-sample numbers (`pages.funnel_events` and `/_dop/e` were dropped in 20260924q); the numbers are per funnel page (above).

## Frontend

- **Display time zone: New York** (`America/New_York`), through the `APP_TZ` constant of `src/lib/time-zone.ts`. Every `Intl.DateTimeFormat`/`toLocale*` that shows a date or time passes `timeZone: APP_TZ`; never depend on the server's or the browser's time zone.
- **NY has daylight saving time**: a local day has 23, 24 or 25 hours. "Midnight N days ago" is `localMidnight(now, N)`, never `midnight - N * 24h`.
